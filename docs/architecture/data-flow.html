图 1-1　系统数据流程图（实线为数据写入链路，紫色虚线为结果回推链路）

图中三处改动对应的设计决策

  1. 结果回推链路（紫色虚线）：原始方案中 Flink 只向下写 MySQL / Redis，没有任何通道回到前端。补一个 exam.result 主题后，Spring Boot 以消费者身份收到即可广播，链路延迟从轮询的 1~3 秒降到百毫秒级，且不引入新组件。
  2. 双通道聚合：累积型指标（平均分、排名、知识点正确率）走事件驱动的增量更新与 upsert；速率型指标（在线人数、每分钟交卷数）走滚动窗口。二者混用是常见错误——用窗口算“当前平均分”会导致每个窗口各算各的，大屏数字跳变。
  3. Redis 双向箭头：Flink 启动时通过 open() 把标准答案全量加载进内存并定时刷新，同时把计算结果作为热数据写回。一场考试的答案量级在千条以内，无需引入 Flink CDC 维表 Join。
